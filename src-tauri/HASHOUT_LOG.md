# src-tauri hashout log

- Engine start (0.27.0): the engine is still started through tauri-plugin-shell (`sidecar`, or the macOS engine folder through `command`), as before; on Windows `win_job::hold_pid` puts it in a job object that ends it, and everything it started, when the app ends however it ends (`win_job.rs` is FormVis's file unchanged; `kill_backend` also ends the job). `engine_start.rs` holds the plain parts: `ADDRESS_WAIT` is 90 seconds with no way to extend it (the old "Keep Waiting" loop is gone), the sentence for each failure, the last 12 lines the engine printed, and the log's path (`~/Formfabric/Logs/formfabric-engine.log`, or the folder `--user-data-dir` or `FORMFABRIC_DATA_DIR` names). `engine_failed` shows that dialog before the splash, the only window at that point, is closed. The shell gives the engine its process id in `FORMFABRIC_SHELL_PID`; the engine still reads `FFB_PARENT_PID` from an older shell. `windows-sys` 0.61 (already in `Cargo.lock` through Tauri) is a Windows-only dependency for the job object. The window key still reaches the engine in `FFB_WINDOW_TOKEN` and the page through the initialization script.
