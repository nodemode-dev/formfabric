- Fault: 0.25.2, the first FormFabric build sent to Apple's notary (formcompiler run 44438017114, submission 0dbca56d-2872-43d6-ac09-5fab06e20ebc), was refused as Invalid for one file, `_internal/Python.framework/Versions/3.14/Python`: "The signature of the binary is invalid." ## v0.24.0 · 2026-11-15

Pre-release audit of `backend/` and `python/`.

- `services/engine.py` :: `dispatch`, `_REBASE`: `file.new`, `file.open` and `exchange.import_dxf` are recorded by the journal but refused by `recovery.replayable`, so a crash before the next autosave restored the later edits onto an empty or wrong document. After one of these succeeds, and only while this process owns the journal, the engine saves the autosave file inside the same lock hold and `recovery.checkpoint()` cuts the log there, so the journal never has to replay them.
- `services/engine.py` :: `_in_autosave_folder`: a save or open inside `[data dir]/autosave` (the autosave itself, the recovery base) is no longer added to the recent list.
- `services/recovery.py` :: `active()`: true while this process owns the journal. `services/autosave.py` :: `save_now` does nothing without it: a second service on the same data folder, or the stdio MCP process, used to overwrite the owner's `autosave.ffbrc`, the base its journal replays onto. A second service therefore has no autosave and no crash recovery.
- `main.py` :: `lifespan`: an `OSError` from `recovery.start()` (disk full, a locked or unwritable autosave folder) is printed and the service starts without the journal, where it used to stop with `Application startup failed`. Shutdown also calls `cmd_chat.cancel()`, so a `claude -p` child of the Chat tab does not outlive the service.
- `formfabric_engine.py` :: `main`, `boot_backend`, `boot_backend.bat`: uvicorn gets a graceful shutdown limit of 1 second. Without it a connected `/api/events` stream kept a stopping service in `Waiting for connections to close` for ever: the desktop shell then killed it after 1.5 s before `recovery.close()` ran (so the next launch offered a recovery after a normal quit), and `--reload` could not restart the worker while a window was open. `setup/serve` still starts uvicorn without the limit.
- `services/scripting.py` :: `run_file`: a plugin that ends with `sys.exit()` or another non-`Exception` exit is reported as a plugin failure, not a bare 500.
- `mcp_stdio.py` :: `main`: stdin and stdout are set to UTF-8 (stdout with `\n` line ends). On Windows a pipe defaults to the ANSI code page, which garbled names outside it and stopped the server on a byte the code page lacks.
- `routers/mcp.py`: `params`, `_meta` or a tool `name` of the wrong JSON type answer `-32602` with status 400, not a 500. `consent` is `async` so `agents.answer` sets the `asyncio.Event` on the event loop thread, not from a worker thread.
- `routers/terminal_socket.py` :: `attach`: a JSON frame that is not an object is ignored, where it used to end the socket with an `AttributeError`.
- `routers/system.py` :: `shutdown`: `POST /api/shutdown` (window rule, like dispatch) closes the journal before it replies, raises SIGINT 0.2 s later so uvicorn stops in its normal way, and ends the process itself after 3 s if that has not happened. It exists for the desktop shell on Windows, which can only hard-kill the service, so that a normal quit is not offered as a recovery on the next launch. No final autosave is written, because a clean journal is never read. Until the shell calls it, Windows quits still leave the journal open.

### Garment library for Home

- `services/library.py`, `routers/library.py`: the library is `[data dir]/Garments`, flat, `.ffbrc` files only; it is the default save place the window offers. A garment's id is `g_` plus 20 hex digits of the SHA-1 of its resolved path, so one id scheme covers library files and recent files outside it. `garments()` lists the library folder plus the entries of `recent.json` that live elsewhere, newest use first; each carries `library: true|false`.
- The rule from decision H7 is in one place, `move_to_trash`: a file is moved only when `in_library()` holds (a regular file, not a link, directly in the library folder). Anything else answers 400 and the window offers Remove from recent (`forget`), which only edits `recent.json` and drops the cached preview.
- Trash is `[data dir]/Garments/.trash/[id]-[unix seconds]/` holding the project file under its own name, `meta.json` and the preview. The entry name is the restore metadata and is checked against `TRASH_ENTRY`; `_entry()` also requires a real folder whose resolved parent is the trash folder, so no request path can leave it. Restore moves the file back, or beside the name as `name (restored).ffbrc` when taken. Moves are `os.replace` inside one folder tree; copies and JSON go to a temp file in the target folder first (`_write_atomic`, `_copy_atomic`, `place`).
- Request text never becomes a path directly: ids, trash entries and template ids are matched against a pattern and then looked up; a title or uploaded file name goes through `clean_name()` (no separators, control characters or reserved device names, 80 characters) and `_free()` picks a name that does not exist.
- `PUT /api/garments/thumb?path=` takes the preview by path, not by id, because the window knows the path it just saved and not the id; the path must resolve to a listed garment. 2 MB limit, PNG, JPEG or WebP by signature. Previews live in `[data dir]/thumbs/[id].img` for library and outside garments alike and are served with the type their signature says.
- Templates are the four shipped projects in `assets/samples` (decision H14); `templates_dir()` reads `FFB_TEMPLATES`, then the frozen bundle (`sys._MEIPASS/assets/samples`, added to `setup/freeze_backend` and its `.bat` twin), then the repo. Creating from a template copies the file into the library and returns its summary; the window then opens it with `file.open`. A blank garment is still `file.new` in the engine and has no file until it is saved.
- `POST /api/garments/import?name=` takes raw bytes (no multipart parser in the path): a `.ffbrc` must be a zip with `manifest.json` and lands in the library, a `.dxf` lands in `[data dir]/Imports` and the window imports it into a new document. 512 MB and 64 MB limits, written to a temp file while streaming.
- `GET` routes use `require_window_read`, every route that changes a file `require_window` (window token or exact origin, loopback Host), as `routers/system.py` does.
- `services/recent.py` :: `forget`, `entries`; `routers/system.py` :: `DELETE /api/recent` (optional `path`): Clear Recent in the window used to clear only its own copy and the list came back on the next open.
- Pin and hide lists of Home are `[data dir]/home.json`, returned with `GET /api/garments` and changed by `POST /api/garments/settings`.
- Open: the library is flat, so a project saved into a subfolder of it counts as outside; the panel count on a card is read from `garment.json` inside the project zip and cached by size and modification time.

## v0.1.0 to v0.3.0 · 2026-10-31

### Shape

- Ported from formsculpt's service (Apache-2.0, nodemode-ai): core (isolation, loopback guard, prefs, quiet log), the terminal, Claude Code, chat, agents, commands and outbound services and the terminal socket were copied and renamed region by region. `main.py`, `core/config.py`, the system, engine, events, plugins and MCP routers, and the engine, events and autosave services are new files built on formsculpt's structure.
- Dropped from formsculpt: the NodeMode, lightbox and GoF routers and the mesh, boolean, stroke, import and export engine routes. GoF returns in Phase 17 as a contract with formsculpt's owner.

### Engine

- `services/engine.py` imports `ffb_engine`; without it every engine route answers 503 with `the engine module is not built; run ./formfabric engine build`.
- `engine.changed` is published inside `services.engine.dispatch`, not in the route, so HTTP, MCP and plugins all broadcast it. Autosave passes `notify=False` so its own save does not wake the window.
- `GET /api/engine/stream` returns the engine's `stream_info()`: the port and token of the native frame server. Frames never pass through Python.
- Recent projects: `services/recent.py` keeps up to 20 paths in the data dir, recorded after every successful `file.save` and `file.open`, pruned of missing files; `GET /api/recent` serves them.

### Events

- `/api/events` is a server-sent events stream in formsculpt's shape (a `hello` first, one JSON message per event, `: ping` every 15 s). It was briefly a WebSocket; it changed to SSE so the chat dock and the engine share one channel. `/api/events/recent` and `/api/chat/image/{name}` stay because the chat service uses them.

### MCP

- `POST /api/mcp` serves MCP over HTTP from the catalogue; status, window and consent live under `/api/mcp/*`.
- `app/mcp_stdio.py` is a newline-delimited JSON-RPC stdio server that runs `ffb_engine` in process with its own `Engine`, separate from a running service. formsculpt's stdio entry proxies to HTTP instead; formfabric runs in process so an agent needs no service running. `services/mcp_tools.py` holds the tool list, result shaping and instructions both transports share.

### Process

- `formfabric_engine.py` is the PyInstaller entry. With `FFB_PORT` unset or 0 it finds a free port before uvicorn starts, so the `Uvicorn running on http://127.0.0.1:PORT` line the shell reads names the real port. `FFB_PARENT_PID` makes it exit with the desktop shell. `--selfcheck` imports the whole app and exits 0 even before the engine module is built (it reports `engine_built`).
- Autosave: every 180 s (`FFB_AUTOSAVE_SECONDS`) into `[data dir]/autosave/autosave.ffbrc`, only when the engine epoch moved since the last save.
- Plugins follow formsculpt's PARAMS model; folders `backend/plugins` and `~/.formfabric/plugins` or `FFB_PLUGIN_DIR`.
- Window token (v0.10.0): the desktop shell makes a 32-byte token per launch and passes it as `FFB_WINDOW_TOKEN`; `./formfabric boot` generates one too. With a token set, `window_guard` accepts only the `x-ffb-window` header (constant-time compare), or, on the terminal WebSocket, the token as the first text frame within 5 s; without one it falls back to the exact-origin rule and logs a warning. Since v0.12.0 the service pops the token from its environment after reading it (children never inherit it), and a token under 32 characters fails closed. `/api/events`, `/api/events/recent` and `/api/recent` follow the window rule; print images come from `/api/files/image`. Every guarded route also requires an allowed Host (127.0.0.1 or localhost on a configured port) against DNS rebinding. `GET /api/mcp/window` is read-only; the window marks itself live with `POST /api/mcp/window`.
- Env names: `FFB_PORT`, `FFB_DIST`, `FFB_DESKTOP`, `FFB_CORS_ORIGINS`, `FFB_AUTOSAVE_SECONDS`, `FFB_PLUGIN_DIR`, `FFB_CLAUDE_BIN`, `FFB_AGENT_DIR`, `FFB_ACCESS_LOG`, `FFB_PARENT_PID`, `FFB_TERMINAL`, `FFB_ENGINE_URL`, `FFB_MCP_URL`, `FORMFABRIC_DATA_DIR`.

### Requirements

- Pins follow formsculpt: fastapi 0.141.1, uvicorn[standard] 0.53.0, python-multipart 0.0.32, maturin 1.11.5, ptyprocess 0.7.0, pywinpty 3.0.5 on Windows, pyinstaller 6.22.3 for the desktop freeze. pydantic and websockets come in transitively, unpinned, as in formsculpt.
